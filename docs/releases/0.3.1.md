# cripsy-binary-api 0.3.1

Parche compatible que ordena la documentación y los scripts por bróker y
completa el binding Python y su distribución.

## Rust (crates.io)

```powershell
cargo add cripsy-binary-api@0.3.1
```

- `Broker::iqoption_extras` permite acceder a las capacidades exclusivas de IQ
  Option desde `Box<dyn Broker>`; el resto de adaptadores hereda `None`.
- Sin cambios incompatibles: `IqOptionExtras` sigue siendo el trait específico y
  los métodos inherentes de `IqOptionBroker` no cambian.

## Python (wheel nativo)

- `buy_digital`, `buy_blitz` e `indicators` en el `Client`; en Deriv se rechazan
  con `CripsyError`.
- Wheels para Linux x64/arm64, Windows x64/arm64 y macOS Intel/arm64, más sdist.
- Publicado en PyPI como `cripsy-binary-api==0.3.1`.

## Documentación y scripts

- `docs/iqoption/` y `docs/deriv/` con la misma estructura temática.
- `docs/python/` y `docs/herramientas/` separados.
- Assets movidos a `img/`; `docs/assets/` deja de existir.
- `scripts/iqoption/` y `scripts/deriv/`; los globales quedan en `scripts/`.
- Corregida la consulta de payout de Deriv: activo y duración, no importe.

## Verificación

- `cargo test`: 85 passed, 0 failed.
- `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings` y
  `cargo check --no-default-features --features blocking`: sin errores.
- Binding: `cargo clippy --manifest-path python/Cargo.toml -- -D warnings` y
  pruebas offline.
- Documentación generada: 18 páginas, grupos General, IQ Option, Deriv, Python y
  Herramientas.
- Wheels construidos por el workflow de seis plataformas y publicados en PyPI.

## Limitaciones que siguen siendo de diseño

- La superficie Python es sincrónica; el núcleo async se usa internamente.
- Deriv mantiene rise/fall y su API async; no se añade fachada `SyncBroker`.
- Multiplicadores, acumuladores, dígitos y barreras quedan fuera del alcance del
  producto.
