# cripsy-binary-api 0.3.3

Parche de alineación de crates.io. Publica el mismo código de `0.3.2` desde un
commit limpio, incorpora la documentación revisada y corrige la metadata de
procedencia del paquete anterior. No cambia la API ni el comportamiento.

## Rust (crates.io)

```powershell
cargo add cripsy-binary-api@0.3.3
```

- La API es la misma que `0.3.2`: `PayoutQuote`, `quote_payout` y el resto del
  contrato no cambian.
- El paquete se genera desde un árbol limpio, por lo que
  `.cargo_vcs_info.json` apunta al commit de esta release.
- `0.3.2` sigue siendo válido; esta versión solo corrige la procedencia y la
  documentación publicada.

## Python

- El binding sigue en `0.3.1`; no se publica un wheel nuevo en PyPI.
- El workflow `.github/workflows/wheels.yml` solo construye y adjunta wheels
  cuando se ejecuta manualmente o cuando el tag `v*` coincide con la versión de
  `python/Cargo.toml`. El tag `v0.3.3` no coincide con Python `0.3.1`, así que
  se omite sin generar un release de Python.

## Verificación

- `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test`
  (89 passed) y `cargo build --no-default-features --features blocking`.
- `cargo test --features blocking`: 89 passed, 0 failed.
- `scripts/build_docs.ps1`: 18 páginas.
- `cargo package` verificado sin `.env`, `target`, `python/` ni artefactos
  temporales.
- `cargo publish` desde el commit limpio y tag `v0.3.3` sin disparar la
  construcción de wheels de Python.

## Limitaciones

- `0.4.0` sigue pendiente: suscripciones gestionadas, ciclo de órdenes y
  paridad Python no forman parte de esta release.
- El binding Python continúa en `0.3.1` y no expone `quote_payout`.
