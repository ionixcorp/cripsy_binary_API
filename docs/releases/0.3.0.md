# cripsy-binary-api 0.3.0

Release con el segundo bróker (**Deriv**) y el binding **Python**.

## Rust (crates.io)

```powershell
cargo add cripsy-binary-api@0.3.0
```

- Deriv sobre la API moderna: REST + OTP + WebSocket, modo público sin
  credenciales y cuenta demo/real.
- Órdenes rise/fall, cierre por evento, historial paginado y reconciliación de
  cierres ocurridos sin conexión (72 s verificados, un solo evento, sin reenviar
  la orden).
- `subscribe_ticks` en el contrato universal, con rechazo explícito en los
  adaptadores que no lo ofrecen.
- Capacidades exclusivas de IQ Option en `IqOptionExtras`; `Box<dyn Broker>`
  requiere migración (ver CHANGELOG).
- 85 tests, clippy sin warnings y variante `blocking` compilando.

## Python (wheel nativo)

- PyO3 + maturin, wheel `abi3` para CPython 3.10+.
- Misma superficie para IQ Option y Deriv: catálogo, velas, ticks, payout,
  balance, compra/venta rise/fall y espera de cierre. En IQ Option añade
  digital, blitz e indicadores; Deriv los rechaza de forma explícita.
- Wheels de Linux x64, Windows x64, macOS arm64 y sdist adjuntos a este
  release.
- Publicación en PyPI pendiente de `PYPI_API_TOKEN`; el workflow
  `.github/workflows/wheels.yml` ya construye Linux, Windows y macOS.

## Verificación

- `cargo test`: 85 passed, 0 failed.
- `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`,
  `cargo check --no-default-features --features blocking`: sin errores.
- Deriv en vivo: 89 activos, ticks en 6 activos, compra/venta demo
  (`Win(0.21)`), reconexión con OTP nuevo (2 396 ms) y reconciliación tras 72 s
  sin red.
- Binding Python: import, 89 activos, velas, payout y ticks contra el gateway
  público de Deriv; pruebas offline del módulo.

## Limitaciones

- Deriv no tiene fachada sincrónica en Rust; el binding Python es sincrónico por
  diseño.
- La densidad de Deriv solo se midió con el gateway público.
- El árbol de trabajo se publica con commit y etiqueta; el crate 0.3.0 ya estaba
  publicado antes de este release.
