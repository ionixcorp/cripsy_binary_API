# cripsy-binary-api 0.3.2

Parche aditivo del crate Rust: añade una cotización de payout explícita para una
combinación de activo, tipo de opción y expiración. No cambia firmas existentes
ni publica una nueva versión del binding Python.

## Rust (crates.io)

```powershell
cargo add cripsy-binary-api@0.3.2
```

- `PayoutQuote` distingue una cotización real de la ausencia de datos mediante
  `available` y `Option<f64>`; una cotización no disponible no se representa
  como `0.0`.
- `Broker::quote_payout(symbol, option_type, expiration_seconds, amount)` tiene
  una implementación por defecto que devuelve `available: false`. Los
  adaptadores que pueden cotizar la sobrescriben.
- Deriv consulta `proposal` para `OptionType::Binary` y la traduce a `CALL`.
  Digital y Blitz devuelven no disponible; un rechazo del bróker se propaga.
- IQ Option consulta Digital por
  `price-splitter.client-price-generated`, espera como máximo 15 s y devuelve
  no disponible si no llega la cotización. Binaria, turbo y Blitz devuelven no
  disponible.
- La cotización de IQ usa el lado `CALL` del strike spot. `PayoutQuote` no
  transporta dirección; no se asume que `PUT` pague lo mismo.

## No incluido en esta release

- El binding Python sigue en `0.3.1`; no se publica un wheel nuevo en PyPI.
- `0.4.0` no está terminado: suscripciones gestionadas, ciclo de órdenes y la
  paridad Python del plan siguen pendientes. Esta release no afirma lo
  contrario.

## Limitaciones

- `quote_payout` usa `CALL` como referencia y no transporta dirección.
- IQ Option solo cotiza Digital por esta vía; Binaria, turbo y Blitz devuelven
  `available: false`.
- Deriv Digital devuelve `available: false`; la cotización viva verificada es
  rise/fall.
- No se enviaron órdenes reales durante esta verificación.
